# Mill Radius Estimator — прототип

Веб-сервис оценки диаметра/радиуса режущей части фрезы по фото с телефона,
через калибровочную ArUco-метку.

Это **рабочий MVP-скелет** (вариант B — обработка на сервере), реализующий
идею из обсуждения:
- калибровку масштаба по эталонному объекту (напечатанная метка);
- измерение диаметра через гомографию "пиксели → мм";
- вывод диаметра, радиуса и оценки погрешности.

Автоматическая ML-сегментация фрезы **не включена** — в этой версии
пользователь сам отмечает две точки на противоположных краях режущей
кромки (см. раздел "Как это работает" и "Дальнейшие шаги" ниже, почему
так сделано для MVP).

## Структура проекта

```

│   ├── measure.py           # детекция метки, гомография, измерение

│   └── requirements.txt
├── frontend/
```

## Запуск

### 1. Бэкенд

```bash
cd backend
pip install -r requirements.txt
uvicorn app:app --host 0.0.0.0 --port 8000 --reload
```

Проверка: `curl http://localhost:8000/api/health` → `{"status":"ok"}`

### 2. Калибровочная метка

```bash
cd backend
python3 marker_generator.py --size-mm 40 --out marker_40mm.png
```

Распечатайте `marker_40mm.png` **на 100% масштаба** ("Actual size",
не "Fit to page" / "Вписать в страницу" — иначе калибровка будет неверной).
На листе есть контрольная линейка 50мм — сверьте её обычной линейкой
после печати, чтобы убедиться, что принтер не масштабировал изображение.

### 3. Фронтенд

`frontend/index.html` — статический файл, открывается прямо в браузере.

**Важно про камеру на телефоне**: `getUserMedia` (доступ к камере)
работает в браузере только в "secure context" — то есть по HTTPS,
или на `localhost`. Варианты для теста с реального телефона:

- **Локальная сеть + туннель** (проще всего): запустите `ngrok http 8000`
  для бэкенда, а фронтенд — через `python3 -m http.server` + свой туннель,
  либо разместите оба за одним HTTPS-обратным прокси.
- **Деплой на любой хостинг с HTTPS** (Render, Railway, VPS с Caddy/nginx
  и Let's Encrypt) — самый устойчивый вариант для реального использования.

В `index.html` в начале `<script>` задан `API_BASE` — поменяйте на адрес
вашего задеплоенного бэкенда (`window.MILL_API_BASE = 'https://...'`
можно выставить прямо перед подключением скрипта).

## Как это работает

1. Пользователь открывает страницу с телефона, разрешает доступ к камере.
2. На превью раз в ~0.9с кадр отправляется на `/api/detect-marker` —
   бейдж сверху показывает, найдена ли метка (зелёный = найдена).
3. Пользователь снимает кадр, где в одной плоскости лежат метка и фреза.
4. На фото пользователь кликает 2 точки — противоположные края режущей
   кромки (это и есть диаметр).
5. Кадр + точки + размер метки отправляются на `/api/measure`.
6. Сервер (`measure.py`):
   - находит 4 угла метки (`cv2.aruco`);
   - строит гомографию `H`, переводящую пиксели плоскости метки в мм
     (`cv2.findHomography`);
   - переводит обе кликнутые точки в мм через `H` и считает расстояние
     между ними — это диаметр;
   - оценивает погрешность из (а) ошибки репроекции углов метки через `H`
     и (б) неопределённости клика пользователя (~2px), пересчитанной
     в мм через локальный масштаб рядом с точками.

## Ключевое ограничение геометрии

Гомография строится для **одной плоскости** — плоскости метки. Диаметр
считается корректно только если измеряемый край фрезы находится **в той
же плоскости**, что и метка (плашмя на одной поверхности, камера может
быть под углом — гомография это компенсирует). Если фреза приподнята
над плоскостью метки или её ось не перпендикулярна этой плоскости,
результат будет систематически смещён — это фундаментальное свойство
измерения по одной плоскости, а не баг.

Практический вывод для UI/инструкции пользователю: класть фрезу и метку
на один и тот же стол/лист, торцом (или тем сечением, где мерим диаметр)
на одной высоте.

## Дальнейшие шаги (roadmap)

1. **Автосегментация фрезы**: заменить ручной клик двух точек на
   ML-сегментацию (YOLOv8-seg / U-Net), обученную на датасете фото фрез,
   чтобы автоматически находить ось инструмента и измерять диаметр
   перпендикулярно ей в зоне кромок. Ручной клик, реализованный сейчас,
   специально оставлен как понятный fallback и как способ быстро
   набрать датасет реальных фото + разметки для будущей модели.
2. **Множественные замеры**: попросить 2-3 фото под разными углами,
   усреднить результат — снижает случайную ошибку клика/фокуса.
3. **Автоопределение локального фокуса/резкости** в зоне клика — сейчас
   погрешность от размытия границы не учитывается отдельно, только через
   фиксированную оценку в 2px.
4. **Иные эталоны** (монета, шестигранный ключ) — сложнее, чем ArUco,
   так как сами требуют детекции; можно добавить как альтернативу для
   случаев без принтера, но с более широким доверительным интервалом.
5. **Продакшн-деплой**: HTTPS обязателен, сузить CORS, добавить лимиты
   на размер загружаемого фото, rate limiting.
